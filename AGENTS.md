# AGENTS.md

Правила работы в этом репозитории. Написаны под текущее состояние проекта, а не абстрактно: если правило противоречит коду, сначала правь код или это правило.

## Что это за проект

Веб-приложение для построения сечений куба по трём точкам. Bun раздаёт статику, фронтенд - three.js, собирается в один минифицированный бандл `public/dist/app.js`. Единица геометрии куба: рёбра длиной 2, от −1 до 1 по каждой оси.

## Команды

```
bun install            # зависимости
bun start              # сборка + сервер на http://localhost:3000
bun run dev            # сборка + сервер с автоперезапуском
bun run build          # только сборка бандла
bunx tsc --noEmit      # проверка типов, обязательна перед правкой сдачи
```

Сервер пишет логи в `tmp/`: `server.log`, `server-404.log`, `server-errors.log`.

## Публикация

`.github/workflows/pages.yml` собирает бандл и выкладывает статику на GitHub Pages
при каждом пуше в `main`. В артефакт идут `index.html`, `styles.css`, `fonts/` и
`dist/app.js`; `server.ts` и `public/src/` остаются локальными. В `Settings → Pages`
источником должен быть выбран GitHub Actions.

**Пути в `index.html` и `styles.css` относительные, без ведущего слэша.** На
проектной странице `user.github.io/repo/` абсолютный путь отрезает префикс
репозитория, и всё уходит в 404. Проверяется только так: собрать `_site` и открыть
её на вложенном пути, а не из корня.

```

public/styles.css   стили
public/src/

  model.ts          типы объектов, фабрики, Store с undo/redo
  colors.ts         палитра сцены: базовые цвета видов, палитры, `cssColor`
  hints.ts          тексты интерфейса: `NO_TARGET_HINT` (сообщения об ошибке), `DEMO`
  help.ts           справка по управлению в виде термин-описание
  icons.ts          значки панели на SVG
  objects3d.ts      построение three.js-сцены из документа
  viewer.ts         сцена, куб, оси, пикинг, превью, рендер-цикл
  main.ts           инструменты, мышь, панели, клавиатура
```

`tsconfig.json` включает `public/src`, `server.ts` и `tests`. Каталога `tests` сейчас нет.

## Правила, которые уже ловили ошибки

**Собирай перед проверкой в браузере.** Сервер отдаёт `public/dist/app.js`, а не исходники. После правки `.ts` без `bun run build` браузер продолжает работать на старом коде, и баг выглядит несуществующим или, что хуже, воспроизводится уже исправленным. `bun start` собирает сам, `bun run server.ts` - нет.

**`tsc --noEmit` после каждой правки типов.** Проект в `strict`, и ошибки типов вылезают сразу, пока контекст ещё свежий.

**Проверяй логику фильтрации по смыслу, а не по форме.** Условие в `filter` описывает, что ОСТАЁТСЯ. Здесь уже был баг с инвертией: `filter((o) => !o.fixed && ids.includes(o.id))` оставлял ровно те объекты, которые следовало удалить, и выбрасывал остальные. Симметрично: в `remove` углы куба защищены выражением `o.fixed || !ids.includes(o.id)`.

**Индекс грани приводи к `null` один раз, в `faceOf()`.** `faceOf()` в `geometry.ts` возвращает `number | null` сразу. Отрицательным индексом пользоваться нельзя: `FACES[-1].normal` уронит обработчик `pointermove` и пропадёт вся отрисовка превью. Свою обёртку, возвращающую `number` из `pointFaces`, не пиши.

**Квад грани обязан лежать в плоскости своей нормали.** В `FACES` квады `z` и `x` были переставлены местами: нормали верные, а вершины от другой грани. Рисунок и превью считали по-разному, и горела не та грань - верхняя с нижней работали, боковые нет. Проверяется арифметикой: все четыре вершины квада должны давать `dot(normal, v) == HALF`. Порядок вершин идёт по кругу, иначе треугольники сложатся в «бабочку».

**`faceOf()` проверяет куб, а не одну плоскость грани.** Точка на прямой, ушедшей за пределы куба, лежит в плоскости грани и за её краем. Считать такую грань нельзя ни для подсветки, ни для цепочки, поэтому `insideCube` стоит первым, а `pointFaces` проверяет то же самое, иначе превью и цепочка решат по-разному.

**Не возвращай из геометрии приблизительный результат там, где доступно любое место.** Перебор отсчётов по отрезку даёт прилипание к дискретным «ступенькам», и это выглядит как сетка. Минимум расстояния между лучом и отрезком решается точно, см. `closestPointOnSegmentToRay`.

**Углы куба неприкосновенны.** У них `fixed: true`: их нельзя удалить, перетащить, и они не попадают в счётчик имён, иначе первые пользовательские точки назывались бы «Точка 9». `store.remove` и `store.clear` обязаны их сохранять.

**Точки вне граней - норма, а не сбой.** Такие точки получают `face: null`. Превью для них обязано разворачиваться лицом к камере, потому что опорной грани для ориентации кольца нет.

**`resolveTarget()` - единственный источник позиции.** Через него идут и превью, и сам клик. Не дублируй логику выбора цели в обработчиках событий, иначе подсветка разойдётся с результатом.

**Прямая и плоскость строятся только по точкам, грань для них не цель.** В `resolveTarget()` это ветка `pointOnly` и `isPointOnlyTool()`. Добавлять новую цель инструменту «Точка» нельзя вслепую: она тут же станет доступна «Прямой», и прямая начнёт липнуть к самой себе, см. ниже.

**Соседство по грани в цепочке проверяется пересечением множеств, а не равенством индексов.** Точка на ребре принадлежит двум граням, вершина - трём, поэтому бери `pointFaces`. Одиночный `faceOf` годится только для подсветки одной грани, но не для проверки соседей.

**Соседство по грани не заменяет проверку на принадлежность плоскости.** Цепочка может пройти шесть граней куба и не быть плоской. Плоскость строится по первым трём точкам, остальные сверяются через `planeSigned` по модулю - знак безразличен, важен факт принадлежности.

**Ошибки называют виновника, а не факт.** «Точки не лежат в одной плоскости» бесполезно, когда в цепочке семь точек. Сообщение должно перечислять конкретные точки и, для соседей, их грани через `FACE_NAMES`.

**Ввод хранит имена, а не только координаты.** `pending` - это `PendingPoint`, иначе ошибки не смогут сказать, какая именно точка не подходит.

**Кнопка «Притягивание» обязана гасить всё, а не только рёбра и вершины.** Иначе она выглядит работающей и молча ничего не делает - ровно тот баг, который пришлось чинить. Пороги, зависящие от `state.snapEnabled`: `MAGNET_RADIUS`, `CROSS_RADIUS`, `stickRadius` в `pickFaceSurface`. Исключение - `PICK_RADIUS` у «Прямой» и «Плоскости»: они берут точки всегда, иначе ими нельзя пользоваться.

**Отсечение бьёт только по стоящей точке и режет одну сторону за раз.** `resolveTrimTarget()` перебирает точки сцены, а не точки прямой, иначе разрез нечем показать и нельзя отменить. Стороны независимы: это `Trims.start` и `Trims.end`, а снимает одну из них `clearTrimEnd`. Отрезок не хранится - только точки отсечения, из них и из хорды он собирается в `trimmedSpan`.

**Отрезанная сторона закрыта, и «та же точка» считается одним признаком.** В `resolveTrimTarget()` точка пропускается, если у её стороны уже есть разрез и это не он сам: `sameCutPoint()`. Без проверки разрез двигался бы на любую точку закрытой стороны, и правило «автообрезка один раз на сторону» переставало бы что-то запрещать. Признак обязателен общий для цели и для действия в `applyTrim()`, иначе подсказка обещает «вернуть хвост», а клик по другой точке двигает разрез. Допуск - `MAGNET_RADIUS`, тот же, что у магнита.

**Автообрезка в узле срабатывает один раз на сторону.** `autoTrimSide()` возвращает сторону только если она ещё не отрезана: `obj.trim?.[end]` пуст. Иначе каждая новая секущая прямая обрезала бы старой прямой тот же хвост заново, и рисунок менялся бы сам. Ручная отсечка сторону тоже закрывает.

**Автообрезка не трогает узел внутри куба.** Перпендикулярные прямые в одной грани - обычное дело, им отсечение мешает: проверка `insideCube()`, а не `faceOf()`. Разница принципиальная: `faceOf` смотрит только на плоскость грани, поэтому узел на прямой, идущей по ребру куба и ушедшей за его пределы, попадёт в плоскости двух граней и будет ошибочно признан «на грани». Автообрезка работает только для узлов снаружи куба.

**Хорда куба берётся только настоящими пересечениями с рёбрами.** `lineSegmentHit()` вычисляет точку пересечения прямой и отрезка и проверяет её принадлежность отрезку через `pointOnSegment`. Проверять параметр `s` вдоль ребра нельзя: формулы для `t` и `s` верны только для компланарных прямых, а у скрещивающихся дают правдоподобное число, и фантомные точки проходили мимо ядра. Раньше так ломалось отсечение: прямая `B1F` уходила за куб по касательной к ребру, `lineEdgeHits()` возвращала ей лишние точки, `untrimmable()` раздвигала ядро за `B1`, и хвост у `B1` становился неотсекаемым.

**Параметр вдоль прямой измерен в единицах длины.** Точка `b` лежит не на параметре 1, а на `|b − a|`. Считать конец единицей нельзя: ядро в `untrimmable()` перестанет содержать опорные точки, и отсечение отрежет от прямой ту, по которой она построена.

**Граница отсечения зажимается от ядра, а не к нему.** В `trimmedSpan()` начало берётся через `min(lo, t(trim.start))`, конец - через `max(hi, t(trim.end))`. Обратное направление прижимает прямую к ядру: точка отсечения дальше ядра оказывается проигнорирована, и прямая обрывается на краю куба вместо точки разреза.

**Не оставляй мёртвый код.** После удаления инструмента или поля пройдись по ссылкам: типы, фабрики, импорты, отрисовка, README. `tsc` молчит про неиспользуемые экспорты.

**Общее не должно рождаться в двух местах.** Проверка на дубли обязательна перед
каждой новой сущностью: цвет вида - в `colors.ts`, параллельный примитив (`toV`,
`fatLine`, `makeLabel`) - в `objects3d.ts` с экспортом, рёбра и грани куба - в
`geometry.ts` из `VERTICES`/`EDGES`, плоскости отсечения - из `FACES`, правило
`commit` + поиск объекта - в `Store.update`, поиск точки по координатам - в
`Store.pointAt`, нарисованный отрезок прямой или отрезка - в `drawnSpan()`.
Дубль здесь стоит дороже, чем кажется: расхождение копий даёт баг, который
выглядит случайным.

**Отладочные скрипты держи короткими.** Проверка в браузере - это `bun run tmp/probe.ts`, десятки строк. Сканирование экрана сеткой с задержками на каждый пиксель упирается в таймаут и даёт результаты, которые невозможно интерпретировать. На программном рендеринге реальные клики мышью тоже могут не уложиться в таймаут, поэтому состояние проверяют через `page.evaluate`, а курсор двигают отдельно.

**Правь `__store` и `__viewer` осознанно.** Оба лежат на `window` для скриптов в `tmp/`. Это отладочный доступ, а не API приложения.

## Стиль кода

- TypeScript в `strict`, без `any` без необходимости. В `tmp/` - можно.
- Комментарии объясняют почему, а не что. Инвертированный `filter`, защита углов, выбор ближайшей грани - всё это стоит комментария. `// увеличиваем счётчик` - нет. Комментариев на две строки там, где хватает одной, тоже не пиши.
- Имена в коде на английском, комментарии, интерфейс и README на русском.
- Импорт типов через `type`: `type Vec3`.
- Фабрики объектов в `model.ts`, отрисовка в `objects3d.ts`, геометрия в `geometry.ts`, взаимодействие в `main.ts`. Не смешивай слои.
- UI-строки собираются в панели и `help.ts`, а не расписываются по обработчикам.
- CSS - обычные классы, стили в `public/styles.css`, без фреймворков.

## Видимый текст

**Весь текст, который видит человек, лежит в `hints.ts`, `help.ts` и `icons.ts`.** В `index.html`
остаётся только пустая разметка, а наполняет её `renderHelp()`. Правка формулировки не должна
затрагивать обработчики: `flash()` и подписи собираются из этих модулей.

**Никаких ИИ-шрифтов в тексте подсказок.** Ни `→`, ни `—`, ни скобочных пояснений: цепочка
пишется через дефис, а причина ошибки входит в саму фразу. «Точка E вне граней куба, цепочку
из неё не собрать» вместо «Точка E вне граней куба — из неё цепочку не собрать».

**Постоянной подсказки под сценой нет.** Плашка внизу показывает только введённые точки и
скрыта, пока их нет: класс `empty` на `.status` ставит `syncPending()`. Описание приёмов
работы живёт в справке «Управление», повторять его в плашке незачем.

**Ошибка называет виновника и говорит, что делать.** Не «неверная точка», а «У точек E и F нет
общей грани куба: E на z = +1, F на y = −1». Пользователь должен понять, что нажимать дальше.

**Значки рисуются в `icons.ts` на SVG, а не берутся эмодзи.** Эмодзи-глаз выглядит на каждой
системе по-своему, а в тёмной панели выбивается из ряда.

**Насыщенный цвет в хроме означает геометрию.** Цвета объектов сцены не выносятся в панели:
акцент интерфейса - бледная ледяная подсветка, включённый переключатель читается заливкой, а
не зелёным. Исключения два: буквы X, Y, Z в полях координат, они повторяют цвета осей на сцене,
и красный разрушающего действия, но только под курсором. Постоянно красная кнопка в панели
закричит сама по себе и начнёт спорить с цветом геометрии.

**Панели уходят в тень от `#202d3a`, а не светлеют.** Главный сине-стальной цвет держит на себе
и сцену, и хром; панели темнее фона, чтобы взгляд оставался на кубе.

## Проверка перед сдачей

1. `bunx tsc --noEmit` - без ошибок
2. `bun run build` - бандл собран
3. `bun start` и ручная проверка в браузере
4. `bun run tmp/probe.ts` - если менялась геометрия, привязка, модель или отрисовка
5. Сервер остановлен: `Get-Process bun | Stop-Process -Force`

Обновляй README, если менялись инструменты, горячие клавиши или поведение. Он описывает интерфейс для человека, и расхождение с кодом в нём хуже, чем отсутствие описания. Разбор геометрии и правил живёт в `docs/ГЕОМЕТРИЯ.md` - не переноси туда то, что нужно читателю интерфейса, и не дублируй там текст README.
